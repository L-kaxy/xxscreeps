## 交付范围

1. **到期自动退出**：到期档位采集 → 持久化清场任务 → 结束对应 run → 玩家全局退出及赛季 2 全区清场 → 核验保存的当前房间后放行重新落地。不会替玩家放新 Spawn。
2. **独立 API**：`/api/speedrun-season2/leaderboard`、`/api/speedrun-season2/records/:user`、`/api/speedrun-season2/racing`。
3. **独立页面**：`/speedrun-season2`，支持实时榜、各档位最好成绩、玩家所有历史局、分页与空榜；`/api/version` 新增 `Speedrun Season 2` 菜单入口。旧 `/speedrun` 和旧 API 保持原样。
4. **回归和恢复演练**：默认/旧赛季/双赛季完整测试、真实房间处理器流程、真实 HTTP、浏览器检查、运行中及清场中的存档分别跨进程恢复。

**本轮所有文件改动都在赛季 2 mod 内。** 不再修改引擎、classic 或旧 speedrun 文件。第 10 步已保留的唯一公共扩展入口仍是 [classic/spawn/model.ts](/Users/jason/workspace/nodejs/xxscreeps/packages/xxscreeps/mods/classic/spawn/model.ts)，本轮不改它。

### 自动退出的安全边界

- 只消费本赛季 `racing`；校验 namespace、shard、run、room、startedTick、endedTick、账号存在和控制房间范围，不能只根据过期队列里的时间退出玩家。
- 新 run、切回赛季 1、旧房被另一玩家占用，或另一玩家刚完成落地但其房间 next buffer 尚未成为 current，旧计时器都不能发起新区块清场；旧玩家此时手动 respawn 也只执行其普通退出，不能清掉新玩家的区块。
- 成功落地在释放区块门禁前持久化 `speedrun-season2/landing` 标记，填补房间 handover 已发生、异步 run 写入尚未完成的窗口；这里只等待该标记写入，不在门禁内等待玩家锁，避免锁顺序倒置。旧现场没有此键也兼容，下一次落地自然建立。
- 清场任务记录本次 run 身份；恢复时若已被其他 run 取代，则取消旧任务，不停止新局。已有第 10 步任务没有 run 字段也兼容，不需要迁移。
- 不在持有玩家锁时再次调用带相同锁的 `stopRun` / 通用自动 respawn，避免递归死锁。同进程同 tick 的重复到期调用合并；跨进程仍用数据库互斥。
- 已请求的手动清场优先停止计时，不会因为本轮开通自动重开，给提前退出的局补记最终成绩。
- 新赛季采集抛出存储异常时保留 due 待重试；该局还有到期 due 时不开始自动清场。RCL 不足或归属不符仍是无成绩，不会等玩家升级后补记。
- `respawnAfter <= 0` 关闭发起自动重开，但不取消已持久化的清场；`raceBrackets: []` 不建立比赛计时，因而也不发起到期重开。手动 respawn 仍可用。
- 地图不重拍；全部 81 房建筑/施工点按已验收规则清理，**中央九房 E4N4～E6N6 已建成 Extractor 保留**。非中央 Extractor 和所有 Extractor 施工点仍清理。
- claim、Ruin、deposit、power bank 仍使用旧 `speedrun` 全图开关，Invader 仍分区。配置没有新增字段或临时回退到旧赛季配置。

## 已有第 0～10 步现场如何部署

1. **先停止全部服务、保存并备份完整存档和配置。** 不是只备份 terrain；账号数据库与 shard 数据必须属于同一个停服时间点。
2. 正常构建并部署；完整重启 main、processor、runner、backend，不能只重启 backend。
3. **无需再初始化地图、补墙、迁移成绩、清空任何旧表，或修改已经通过的 claim/Ruin 配置。** 未初始化的新副本才按 [STEP3.md](/Users/jason/workspace/nodejs/xxscreeps/packages/xxscreeps/mods/speedrun-season2/STEP3.md) 显式停服初始化一次；不要在既有新区块重新拍图。
4. 打开 `/speedrun-season2`；客户端重新连接/刷新后，从新增 `Speedrun Season 2` 菜单打开。旧入口保留。前置代理必须将新页面和 `/api/speedrun-season2/*` 一并转到本项目 backend。
5. 联合验收只使用测试副本。正式上线和处理测试局另行确认，不由本次代码修改隐式执行。

### 特别注意升级时的旧活动局

**第 10 步以前 `respawnAfter` 尚未执行；升级后开始执行。已有赛季 2 活动局若已超过 40000 tick，会在后续 tick 被自动退出并清场。** 不会重置起点或赠送一个新窗口，也无法补回历史档位时的房间状态。

如需先检查现场，升级前在该环境临时设置 `speedrunSeason2.respawnAfter: 0` 并完整重启；确认活动 run 和备份后再改回正式值。这只阻止发起新的自动清场，**不会取消已经开始的清场任务**。不要通过手工删 cleanup/due/racing 来放行下一局。

正式默认配置保持：

```yaml
speedrunSeason2:
  invaders: false
  respawnCleanup: true
  raceBrackets: [20000, 40000]
  respawnAfter: 40000
```

本轮未修改正式环境 YAML；短档位只在独立临时配置目录内使用。不要为了新赛季测试改线上 `speedrun` 的旧赛季档位。
